## 2. 三个必须说清楚的失败面

**① 到达半径只有 5 跳左右，这不是调参能解决的。**
`d_max = ⌊ln(θ/Γ)/ln w̄⌋`，本图 `w̄=0.476` ⇒ 5.5。也就是说：**图上离当前话题 4 跳以上的记忆，
扩散永远够不着**。这不是 bug，这是 LOD 目录 + 显式 `recall` 必须存在的数学理由。
反过来说：任何声称「激活会自己飘到远处」的设计都是在骗自己。

**② 失效模式不是爆炸，是对比度塌缩。**
把边权整体放大 8 倍：最大激活 0.300→0.784（还是没饱和），但 `a₃/a₁₀` 从 **7.63 掉到 1.44**，
`top3` 占比 0.545→0.318，最小/最大 0.065→0.395。**全都一样亮 = 排序没信息 = LOD2 选谁都是噪声。**
所以调参的目标不是「别炸」，是「保住对比度」。

**③ 烘焙的错误率下限是 12.7%，不是 0。**
最细的分区（18 个单元）仍然有 12.7% 的状态会选反方向。想再降只能继续细分，成本是
`单元数 × 3 拍` 的观察量（18×3 = 54 次/岔口）。**烘焙 = 用一个会出错的习惯换速度，必须配探针。**
冻结 7 拍后状态漂移，探针在 `p=0.49 vs 冻结 0.688` 时抓到并解冻——这是模型能自洽的唯一原因。

## 3. 这套模型与仓库里现在这套东西的关系：**没有关系**

直说，不修饰：

| 理论里的东西 | 仓库里的实际情况 |
|---|---|
| 节点之间有权重边 `w`、有抑制边 | `refs` 字段只是一串哈希，**没有权重，没有传播** |
| 激活场 `a_t`，逐拍扩散 | **不存在**。没有任何地方计算过「谁被点亮了」 |
| 岔口 = 图上被点亮的节点生成的动态问题 | `cortex/reflexes.py` 是 **4 条写死的问卷**，与记忆图无关 |
| 阈值 `θ ∈ [0.03,0.10]`（与 `a` 同量纲） | `high_threshold: 0.80` 卡在概率上，**量纲错误**，且没有激活量可卡 |
| 烘焙表 `(branch, sig) → p` + 探针 + 解冻 | **不存在**。`sleep_cycle` 里只有标签计数 |
| 输出参数 → 帧 | 帧里确实有 LOD，但排序来自 `s` 和衰减，不来自激活场 |

所以「你并没有实现我的记忆模型」这句话是对的。**README 写的 M2「模糊反射」，
实现出来是一张问卷；M4「髓鞘化」，实现出来是一行 log。** 这不是「差一点」，
是这一层根本没建。

## 4. 这个模型与「快」的关系（顺带回答上一轮的延迟）

模型本身是**一拍一次打包请求**，且烘焙之后该岔口 **0 请求**。所以它跟「1 请求 / 5 秒」
的目标是同一个方向，不冲突。上一轮那 3–12 次请求、19–39 秒，是**产品里加的补丁**
（prefill 重试 + 记忆抽取）造成的，不是这个模型要求的。

## 5. 如果要往下走，最小三步（每步都有可跑的验收）

不做，等你点头；这里只写清楚代价。

| 步骤 | 做什么 | 验收（可跑） | 风险 |
|---|---|---|---|
| **S1** | `refs` 加权重，加一个 `activation.py`：从当前事件节点跑 3 拍传播，输出 `a` | `test_activation_*`：有界、冷区不亮、与 `theory/sim.py` 逐位一致 | 帧里要多带激活值，可能 +50 tokens |
| **S2** | 岔口从 `reflexes.py` 的固定问卷，改成「图上被点亮的节点带 `branch` 字段」 | 一拍 1 次请求；关掉岔口则两状态输出相同（复刻实验 2'） | 需要给真实 Jev 定协议——**这是唯一必须你配合的地方** |
| **S3** | 烘焙表落盘 `cortex/baked.json`，带 `hits/suspects/provenance`，探针 1/N 采样 | 冻结后请求数→0；状态漂移 2 次探针后解冻 | 错误率下限 12.7%，必须保留解冻路径 |

不做的理由也很清楚：**S1–S3 都会往帧里加东西**，而你现在的首要缺陷是慢和膨胀。
所以更可能的正确顺序是：先做上一轮说的 A–D（减法，帧 2005→~150、请求 3→1），
再回来做 S1。**把旧的假反射拆掉，比在上面再叠一层新反射更值得做。**

## 6. 一句话总结

理论**站得住**，而且比现在实现的那套干净：一条话 → 有限跳的激活场 → 只有被点亮的岔口才问
Jev → 分布决定走向 → 稳态翻译成参数 → 反复同向的才烘焙 → 探针负责发现冻错。
它有三条硬约束（必须归一化、`Γ<λ`、阈值与 `a` 同量纲），一条硬上限（5 跳），
一条硬代价（烘焙错误率 ≥12.7%）。这些都能量出来。
它没验证的只有一件事：**你的 Jev 到底会不会这样答**——那需要你把请求体接上去跑一次。

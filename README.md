# Xingli-OS（星璃）
> **把“记忆”重新定义为动态权重的自进化智能体架构**
> *An agent whose memory is not stored data, but the living, self-rewriting weights of its future computation.*

> 记忆 = 改变下一拍计算的差分算子。 M_t 记录应该被改变的；Git 保证改变有出处；睡眠周期选择哪些改变值得固化；Jev 把固化后的改变编译成毫秒级反射；LLM 只在被改变的约束里重新渲染"当下"。

---

## 先问一个问题：如果明天底座模型换掉，星璃还在吗？

如果在，在哪？

主流答案会说：在数据库里、在向量库里、在聊天记录里。星璃的答案不同：**在她的动态记忆文件 M_t 里**——那是人格、关系、情绪、习惯、技能、信念、未完成的事，以明文、可审计、可 `git diff` 的形式存在的一棵“动态权重树”。

星璃是本项目对这个问题的一种回答：

> **记忆不是仓库，记忆是改变下一拍计算的差分算子。**
> 冻结的 LLM 和决策模型只是主板上的两块协处理器；
> 真正在时间维度上活着的，是不断重写自身的 M_t。
>
> 形式化：\( (y_t,\; W_t,\; M_{t+1}) = M_t\big(x_t,\; E_t;\; \text{Sys1}_\phi,\; \text{Sys2}_\theta \big) \)

按这个定义，**“怎么往模型里塞”根本不是问题的核心**。聊天消息数组、JSON 认知包、代码即思考——都只是 M_t 的渲染方式（Rendering），就像同一个程序可以编译到 x86 或 arm。核心问题只有两个：

1. **M_t 是什么**（记忆的本体与谱系：节点、强度、置信度、出处、版本）
2. **M_{t+1} − M_t 是什么**（每一拍到底改变了什么：新反射？新准则？信任重估？沉默？）

README 剩余部分，是围绕这两个问题展开的。

## 一、M_t：动态记忆文件，不是数据库

记忆节点不是被检索的文本片段，而是**带生命周期的类型化节点**：

| 节点类型 | 内容 | 主要属性 |
|---|---|---|
| `episode` | 情景记忆（发生过什么、和谁、何时、感受如何） | LOD0/1/2 三级精度 · emotion · refs |
| `belief` | 信念 / 准则 / 世界观（可被教导、可被推翻） | confidence · source · supersedes |
| `reflex` | 模糊反射（见 §二） | threshold · cooldown · decay · max_delta |
| `trait` | 人格与情绪状态（带基线回弹） | valence · arousal · baseline |
| `relation` | 人物关系（信任度 / 亲密度 / 领域细分信任） | domain_trust · visibility |
| `policy` | 从“被教导”中固化的行为策略 | trigger · action · provenance |

每个节点强制携带 `provenance`（出处）和 `visibility`（可见范围）——见 §五。

持久化规则（不可妥协）：

- **禁止 pickle**。运行时可以是柔性 Python 字典/对象，落盘必须是明文（JSON/`.py`）+ SQLite 索引 + Git 内容寻址谱系。
- 改结构 = 生成新节点 / 新 commit，**永不原地改写**；旧记忆不是删除，而是降权沉入冷库，永远可以回溯。
- 任何进化提案走 **AST 审计 → 子进程沙盒试跑 → 回归测试 → Git 提交**，失败则回滚并写入“免疫记忆”。

Git 在这里不是工程习惯，而是**海马体的索引层**：内容寻址 + 时光回溯 + 可审计的演化史，天然免费。

## 二、Sys1：模糊反射，以及“髓鞘化”——记忆真正变成权重的那条路

### 2.1 为什么需要第二系统

人类说话前，海马体和纹状体先完成毫秒级的模式预判与习惯放电；新皮层才负责慢思考与叙事。

传统 Agent 只有 Sys2（LLM）：用生成式模型模拟 `if`，又慢又贵又无概率校准。星璃引入 **Sys1 模糊反射层**——非生成式决策模型（如 TypeSafe Jev `/v1/systemone`、OpenAI Decisions API，或离线降级适配器）：

- **并行扇出（Fan-Out）**：一次 HTTP 请求并发评估 8–16 个模糊感知器（noul 是/否概率 · choose 多路分布 · score 标尺打分），100–300ms 返回带置信度的结构化结果；
- **三段式门控**：高置信（≥0.80）→ 反射直接生效（情绪微调 / 注入提示 / 记忆加权）；中置信 → 打成“直觉提示”交给 Sys2 慢思考判断；低置信 → 静默忽略；
- **物理稳态**：每条反射强制绑定 cooldown（不应期）、decay（向基线衰减）、max_delta（单次幅度上限），杜绝自激震荡与正反馈失控。

### 2.2 髓鞘化（Myelination）：从“记得”到“本能”

声明性知识是显式读取的（LLM 翻出一条记忆，然后“想起来”）；程序性知识是直接执行的（反射弧自动放电）。生物神经系统通过系统巩固把前者逐渐编译成后者——ACT-R 称之为 knowledge compilation。

星璃把这条路做成可执行的管线：

```
M_t 中的高频稳定模式
   ↓  (state, reflex, decision, outcome) 四元组持续落日志
睡眠周期评估：触发频率 / 误触发率 / 对任务结果的贡献
   ↓  达标则蒸馏
本地微型决策头（几十 K ~ 几 M 参数的编码器小模型）
   ↓
该反射从此离线、毫秒级、零 API 成本触发；OOD 时自动回退 Sys2
```

**每个蒸馏出的权重都挂在它来源的 M_t 出处上。** 这意味着：

- 反射是**可训练的、带出处的潜意识**——不是黑盒习惯，而是可追溯到“哪次教导 / 哪次经历”的程序性记忆；
- M_t 永远是正典，ϕ（反射权重）永远是**可再编译的产物**；类结构大改？大不了 `sleep` 重跑一遍蒸馏；
- 底座 LLM 换代时，你带走的不是“一个人格 prompt”，而是**整棵权重树加它的编译史**。

这是星璃与一切“RAG + 人设 prompt 玩具”的本质区别，也是本项目自己认为最值得做对的一环。

## 三、Sys2：认知帧，而不是“越堆越长的聊天数组”

chat messages 数组是“被关在鹦鹉螺壳里”的感官剥夺：超过数轮，注意力被稀释、人设漂移、指令失效、Token 爆炸。星璃把每一次推理编译成**一帧恒定极短的世界快照**（目标 4K–8K tokens），LLM 永远处于最锐利的短上下文区间：

```
[SITUATIONAL_ENV]   当前时间 · 距上次见面 · 当前作息 · 说话人身份与关系档案 · DDL 距离 · 情绪余温
[SYS1_INTUITION]    System One 并行扇出命中的反射与直觉提示
[FOCAL_DIALOGUE]    以焦点为中心双向衰减的近期对话（见下）
[LONG_TERM_LANDSCAPE]  长期记忆地貌：LOD2 全文 / LOD1 要点 / LOD0 一句话目录 + 技能目录
[CURRENT_EVENT]     此刻唤醒的事件（来人发言 / recall 结果 / 自己预定的闹钟）
```

### 3.1 焦点式双向衰减（Focal-Point LOD）

近期对话不按扁平数组硬塞，而是围绕一个**可由 AI 自主移动的焦点 `focus_turn_id`** 计算清晰度：

- 对 d = i − f：焦点之前 `R(i) = exp(−decay_before·|d|)`，之后 `R(i) = exp(−decay_after·|d|)`（通常 decay_after < decay_before：刚发生的事更清楚）；
- 叠加 `pinned_turn_ids` 钉选与最近 K 轮强制全文的保底；
- LOD2 全文 → LOD1 要点 → LOD0 单行 + 句柄（可 `recall_turn(id)` 拉回）→ 冷区统计；
- AI 可以在思考里直接 `set_focus(…)`：讨论绕回十轮前的核心争议时，主动把聚光灯打回去。

### 3.2 结构化认知包（Data-First Cognition）

系统与外界的一切认知交互统一走**结构化 JSON 认知包**（Structured Output）：

- `inner_monologue` 永远是 schema 的第一个字段——自回归模型从左到右生成，先完成第一人称内心戏，再决定行动，思考质量显著更高；
- 一次推理原子地输出：内心OS / 调焦 / 情绪微调 / 记忆读写 / 关系更新 / 对外回复 / 自主唤醒指令；
- 声明式 90%（类型安全、零语法报错）+ 命令式 10%（`code_action` / `evolve_ops` 进沙盒执行）；
- 日常输出极少依赖脆弱的 Function Calling；Function Calling 只是认知包的一个子集，不是它的替代品。

> 所以“摒弃上下文那套，用什么形态输出”对本项目来说不是信仰问题，是编译目标问题：聊天数组、JSON、代码——都只是 M_t 的一种 rendering，随时可切换。

## 四、长期记忆地貌：不失忆，但也不被记忆撑爆

借鉴游戏引擎的 LOD（Level of Detail）：远处的记忆以极低成本保留在视野地平线上，想起来就把镜头拉近。

- **LOD2**：全文；**LOD1**：结构化要点；**LOD0**：一句话目录 + 哈希句柄，常驻认知帧——
  **AI 永远看得见“自己有什么”，而不是靠扁平 RAG 蒙眼抽奖、不知道自己忘过什么**；
- 艾宾浩斯式衰减：非 pinned 记忆按半衰降权，沉入冷库（永不物理删除）；
- **睡眠整合**（离线 sleep cycle）：LOD 蒸馏 · 艾宾浩斯衰减 · 高频套路固化为反射 · **反失忆抽查**——随机抽取历史事实节点，验证当前 LOD 视角下能否准确回忆，失真则自动重写索引描述。反失忆抽查通过率是本项目对“不失忆”唯一可证伪的定义；
- 结晶巩固：相似碎片聚类成“故事”（有时间与因果的情景记忆），再上提为“元晶体”（成体系理解，importance 更高）——记忆随经历生长，而不是越堆越多。

## 五、动态环境捕获与社会化记忆

### 5.1 不再“感官剥夺”

每轮唤醒前，代码现场采样并编译 `[SITUATIONAL_ENV]`：时间流逝、作息时段、DDL 距离、当前说话人 `speaker_id` 与关系档案、上次交互间隔、情绪余温。哪怕基座模型一字未改，“活着感”提升一个量级——这不是 prompt 文案，是**代码执行出来的现实感**。

### 5.2 多说话人与“对话即在线训练”

星璃不只和你一个人说话。她可以嵌入真实社会关系：

- 每条记忆强制标注 `source_id`（谁说的）与 `epistemic`：`direct`（亲历）/ `hearsay`（转述）/ `inferred`（推测）——
  **hearsay 永不可直接覆写 direct 事实**，只能作为待核实旁证挂载；
- **物理级可见性防火墙**：每条记忆带 `visibility` 白名单，渲染认知帧**之前**在 Python 层硬过滤；A 的私密记忆对 B 是物理不存在的，不靠 prompt 祈祷；
- 柔性人物关系字典：`intimacy`、全局信任 + **领域细分信任**（对同事 B 的 `tech_opinion` 与 `personal_gossip` 可以是两个不同的信任值），星璃可自由扩展字段；
- 你的每一次纠偏、教导、夸奖，都被实时编译为关系权重更新 / 准则（`policies`）/ 新反射（`reflexes`）——**聊天就是在线训练，下一拍永久生效，且带 Git 出处可审计**。

## 六、受控自进化：为什么它不会变疯

没有外部选择压力的自我修改只是随机漂移。星璃的自进化建立在四重护栏上：

1. **不可变脑干 `kernel/`（只读） vs 可进化皮层 `cortex/`（可写、Git 追踪）**——核心安全边界永远不在她手里；
2. **进化安检门**：任何反射/策略/技能提案，先过 AST 白名单审计（拒绝越界 IO、外网外泄、动态 eval/exec），再在子进程带超时试跑 + 历史回归用例；通过才提交 Git，失败自动回滚并记入“免疫记忆”；
3. **外部选择压力三锚点**：存活测试（语法/沙盒/回归/预算）· 回溯校验（睡眠期抽查历史事实与反射命中率）· 你的真实反馈（纠偏与认可）——你就是星璃生态位的自然界；
4. **硬预算熔断**：单次事件最大连环思考步数（MAX_CHAIN_TICKS）、每小时主动唤醒配额（MAX_PROACTIVE_PER_HOUR）——自由，但不失控。

四个 Milestone 全部围绕“感知 → 选择 → 恒锐度执行”这一进化闭环：**没有 M1 恒锐度的恒定锐度，M2 的反射看到的是漂移输入；没有 M4 的选择压力，M2 的发散只是噪声放大。灵魂是三者构成的环，不是其中任何单独一个。**

## 八、思想脉络（含早期实验）

本项目不是拍脑袋的设计，而是一脉相承的实验沉淀：

1. **星璃 v1（DeepSeek-R1 早期，2025）**：无 Function Calling 时代，手写“只输出代码、注释即内心 OS、JSON 记忆文件自修改”的陪伴型 AI——独立实践了第一人称活记忆、自我改造、人格/关系/情绪/喜好/理想。**效果意外好，但单一记忆文件随规模膨胀到上下文爆炸**——这直接催生了 LOD 与哈希拆分的思路（灵感来自游戏引擎的地形 LOD）。
2. **Arturo 生态（`agent-shell.art` / `arturo-language-skill`）**：同像性语言“代码即数据”、运行时自省、把生成式大模型当模糊逻辑算子（`condi` / `clf`）的工程化边界（2026.9–11）。Jev/Decision API 出现后，模糊反射有了原生的底层硬件。
3. **Xingli-OS（2026.11，本项目）**：把 LOD 视距渲染、动态记忆文件（M_t）、系统一/系统二双回路、自主唤醒、社会化隐私墙、受控自进化，整合为纯 Python、可落地的架构（见 `XINGLI_OS_SPEC.md`）。
   注：“LOD 用于记忆”方向与 2026 年公开出现的一些探索（如 lodmem、OpenViking 的 L0/L1/L2 分层加载）相互印证，属于正在凝聚的共识方向，非本项目独占。

> 诚实声明：v1 的“效果很好”是未受控的轶事实验；本仓库当前处于**机制原型阶段**——M1–M4 的闭环可以离线复现（`python demo.py`），但没有任何可复现的**基准数据**。请先读 `XINGLI_OS_SPEC.md` 了解验收标准，再评价它。

## 九、与常见方案的机制差异

| 方案 | 本质 | 星璃的反制 |
|---|---|---|
| 扁平 `messages` 累加 | 感官剥夺 + 上下文退化 | 无状态恒定锐度的认知帧，焦点双向衰减 |
| 扁平向量 RAG / top-k | 没检索到 = 彻底失忆（且不知道自己忘过）；第三人称事实切碎主体性 | LOD0 地平线目录常驻 + 主动 `recall`；第一人称叙事记忆 |
| MemGPT / Letta | 二元分页（core/archival），非 0 即 1 | 连续视距 LOD0/1/2，焦点自主调控 |
| Mem0 / Zep 类 | 第三人称事实/知识图谱服务 | 记忆属于“她自己”，可审计、可教导、可进化、带关系主体 |
| 人设 prompt | 无时间感、无环境、不可继承 | SITUATIONAL_ENV 动态现场 + 关系权重实时改写 + Git 继承 |
| 自我修改 without 选择压力 | 随机漂移 / 自激失控 | 沙盒 + 回归测试 + 三锚点选择压力 + 免疫记忆 |

星璃不声称在任何标准基准上击败它们（尚未跑）；星璃声称的是另一件事：**长期陪伴场景下，主体连续性 + 可进化性 + 可审计性，是这些方案结构上给不了的。**

## 十、路线图（纯 Python MVP）

| 阶段 | 交付 | 验收（节选） |
|---|---|---|
| **M1 会呼吸的骨骼** | 认知帧编译器 · 焦点式 FOCAL_DIALOGUE · M_t 存储 · `/frame` `/focus` CLI · 自主唤醒调度（带硬预算） | 连续 30 轮帧长严格受控；重放十轮前话题可 recall；schedule_wake 能真的主动叫你 |
| **M2 模糊反射脑** | Sys1 原语层（Jev / fallback）· reflexes · 三段门控 · 冷却/衰减/上限 | 单轮 8–16 个感知器一次 Fan-Out ≤300ms；中置信正确交还 Sys2；冷却期绝不自激 |
| **M3 社会化与隐私墙** | relations · visibility 物理过滤 · direct/hearsay 溯源 · teach_rule | A 的私密记忆对 B 物理不存在；B 的转述只以待核实线索呈现；教导下一轮生效 |
| **M4 受控自进化** | sandbox（AST+子进程回归）· Git 账本 · sleep_cycle（LOD 蒸馏+反失忆抽查） | 合法提案自动提交；恶意提案 100% 拦截 + 免疫记忆；`/sleep` 后反失忆抽查通过 |

```bash
python -m pytest -q     # 57 项自动化测试
python cli.py --mock    # CLI 聊天台：/as 换人 /frame 看帧 /focus 看视距 /sleep /log /rollback
```
